# Calibration Methodology (SECTOR-5A)

## 1. Descriptive vs predictive

A sector that already moved +1.5% with 90% breadth is *descriptively* strong. Calibration
must instead measure **forward** behaviour: after observation time T, does that condition
lead to useful continuation (or reversal)? Every calibrated threshold is justified by
forward evidence, not by explaining past movement.

## 2. No look-ahead (hard rule)

At observation T, features use **only** information with timestamp ≤ T (previous close,
session open, bars completed by T, membership effective on that date). Forward information
(bars after T, day high/low, close) appears **only** in labels. Features and labels are
generated by physically separate passes and stored in separate datasets (see
FEATURE_SCHEMA / LABEL_SCHEMA), so leakage is structurally hard, not merely discouraged.

## 3. Point-in-time membership

Replay resolves SECTOR-2 membership **effective on the replayed date** via the existing
`MembershipResolver.resolve_primary(identity, on=trading_date)`. Today's membership is never
applied retroactively. The current bundled dataset (`nse-sector-membership`, effective
2026-09-02) is a single snapshot; runs record the dataset version and effective-date policy,
and any pre-effective date is flagged `MEMBERSHIP_UNAVAILABLE` (fail-closed), not guessed.

## 4. Historical universe & survivorship

The current F&O universe (210 underlyings) is **not** the historical point-in-time F&O
universe. V1 replay uses the **current-universe retrospective** method and records it
explicitly in run metadata (`universe_methodology = current_universe_retrospective`). This
carries survivorship bias (delisted/removed F&O names absent; names added later present on
dates they were not F&O-eligible). True point-in-time F&O eligibility requires historical
F&O-eligibility snapshots ApexScan does not currently hold — a **SECTOR-5B prerequisite** to
source, else the bias remains a documented limitation. No run may claim unbiased.

## 5. Corporate actions

Historical raw returns break across splits/bonuses/mergers/demergers/symbol changes.
Policy: prefer a **corporate-action-adjusted** daily series for previous-close continuity;
require intraday-day-internal returns (open→T, T→T+h) to be computed **within a single
session** (no cross-session ratios), which sidesteps most adjustment issues for the intraday
horizons. Any date/instrument whose previous-close↔open↔intraday relationship implies an
unadjusted split (heuristic: |overnight_return| beyond a recorded sanity bound) is excluded
with `CORPORATE_ACTION_UNSAFE` and the reason logged — never silently returning an absurd
value. Whether a trustworthy adjusted source exists is a SECTOR-5B data prerequisite.

## 6. Trading calendar & sessions

Use ApexScan's authoritative `MarketSessionClassifier` / `TradingCalendar` (ADR-011) to
enumerate trading dates and intraday session bounds. Holidays, weekends, and special/short
sessions are honoured; horizons and observation times are validated against the *actual*
session for that date, never assumed 09:15–15:30. Calendar-ambiguous dates → `CALENDAR_AMBIGUITY`.

## 7. Data granularity, price reference & timestamp semantics

Provider offers intraday intervals **{1, 5, 15, 25, 60}m** (`/charts/intraday`, ≤90-day
chunks) and daily (`/charts/historical`); canonical `Candle` carries **explicit
`start_timestamp` and `end_timestamp`** and the engine resamples 1m→N exactly
(`divides_exactly`). **Recommendation:** fetch **1-minute base** and resample.

**Price at observation T = close of the completed 1-minute bar whose `end_timestamp ≤ T`**
(the last fully-closed minute at/before T). This is unambiguous given start+end timestamps
and contains no future information. `session_open` = open of the session's first bar;
`previous_close` = prior trading day's adjusted daily close. The exact provider bar-labeling
(does a "09:30" bar cover 09:29–09:30 or 09:30–09:31?) must be **empirically confirmed in
SECTOR-5B** against real candles before trusting the grid; until then it is a recorded
prerequisite, mitigated by keying on `end_timestamp`.

## 8. Observation-time grid

Denser early (ApexScan's momentum window), sparser later. **Research candidate** (not
production): 09:20, 09:25, 09:30, 09:35, 09:45, 10:00, 10:30, 11:00, 12:00, 13:00, 14:00,
15:00 IST. 09:15–09:20 opening noise is **retained** and analysed separately (not excluded).
SECTOR-5C evaluates whether thresholds should be **global or time-of-day dependent** — the
grid is designed to answer that, not to pre-commit to it.

## 9. Primary & secondary outcomes

- **Sector primary (recommended, not frozen):** direction-aligned **15-minute** forward
  sector median return (§LABEL_SCHEMA). Rationale: matches the intraday-momentum use case and
  is long enough to exceed 1m microstructure noise, short enough to be actionable. **Secondary:**
  5m, 30m, 60m aligned returns + forward breadth/dispersion (diagnostics).
- **Stock primary (recommended):** direction-aligned stock forward return AND stock forward
  return **relative to sector** — kept separate (one answers "did it move", the other "did it
  independently outperform"); not combined in 5A.

Direction-aligned = `+return` for a bullish observed sector, `-return` for bearish; undefined
for NEUTRAL/MIXED/INSUFFICIENT (labels `None` with reason). Continuation/reversal are stored
as **continuous** aligned forward returns first; binary thresholds are a 5D calibration output.

## 10. Splits, walk-forward, dependence

Chronological only — **no random row split** (intraday snapshots within a day/stock/sector are
correlated; random splitting leaks). Partition by date into development → validation →
untouched out-of-sample test. Prefer **walk-forward** (calibrate past window → evaluate next →
roll). Bootstrap/confidence intervals resample by **trading day**, not by observation. See
VALIDATION_PROTOCOL for the full protocol.

## 11. Production-math reuse (frozen rule)

SECTOR-5B **must** orchestrate the merged pure functions — `MembershipResolver`,
`calculate_universe_proxy`, `calculate_sector_metrics` (SECTOR-3), `rank_sector_constituents`
(SECTOR-4) — and must **not** re-implement any return/breadth/median/MAD/IQR/rank formula.
This guarantees calibration and live production cannot diverge. The replay layer only:
loads history → builds `ConstituentObservation`s at T → calls production math → writes
features; then a separate pass builds labels from post-T bars.

## 12. ADR fit

SECTOR-5A is methodology consistent with ADR-016 (offline, read-only, reuses production math,
no MarketContext/provider/index change). **No new ADR and no status change** — ADR-016 stays
Proposed; these docs are subordinate design artifacts. A new architectural decision would only
be needed if 5C evidence forces ex-sector proxy or index subscription (explicitly deferred).

## 13. Research questions (investigation designed; answers are 5C outputs)

Q1 earliest reliable time after 09:15 · Q2 09:20 vs 09:25/09:30 · Q3 best momentum horizon ·
Q4 breadth beyond median · Q5 relative strength beyond absolute · Q6 agreement value · Q7
participation value · Q8 dispersion → fragile vs healthy · Q9 sector-size effect · Q10 can
N=1 ever earn confidence · Q11 percentile → stock continuation · Q12 stock_vs_sector →
relative perf · Q13 robust magnitude cross-sector comparability · Q14 useful OPPOSED vs noise
· Q15 persistence value · Q16 bull/bear symmetry · Q17 time-of-day variation · Q18 gap-regime
effect · Q19 universe-regime effect · Q20 whole-universe vs ex-sector for large sectors.
Each maps to a stratified forward-outcome comparison with effect size + chronological
stability (VALIDATION_PROTOCOL); none is answered with an assumed threshold in 5A.
